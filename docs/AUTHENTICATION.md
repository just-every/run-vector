# Vector authentication and mail

Vector uses Base operator-auth at the pin recorded in docs/BASE-ADOPTION.md. Private HTTP routes, documents and Start server functions independently validate ordinary Base sessions. The product mapping admits active operators in the same workspace. Every mutation carries the session ID and operator version into its database transaction; revocation or removal before commit rolls the transaction back. Server modules and credentials stay out of browser bundles and evidence.

Hosted configuration requires the exact HTTPS APP_ORIGIN, explicit FIRST_OWNER_EMAIL/workspace/team fields, a private SESSION_SECRET, MAIL_PROVIDER=sendgrid, MAIL_FROM and MAIL_API_KEY. Provider acceptance does not establish inbox arrival. Rejected, unavailable or uncertain sign-in delivery revokes the issued link and reports failure. Requesting again issues a new link.

POST /auth/request delegates to the native Base magic-link handler; /auth/magic-link is also mounted. Product IP and Base email/endpoint rate limits apply. GET/HEAD /auth/confirm preview without consuming a token, creating a session or setting a cookie. Same-origin POST consumes once. Unfinished installation owners return to /setup; completed owners follow the stored safe return path. Hosted cookies are __Host-operator_session, HttpOnly, SameSite=Lax and Secure. Signout revokes the native session.

Local setup uses private .dev.vars with the same Base authority, an explicit literal loopback origin and MAIL_MODE=local-outbox. /__dev/outbox shows captured mail only for that local installation and only to a request that holds the checkout's dev key (rer setup writes it; rer dev's RER_OPEN link trades it for a cookie). Dev identity signs the browser in as a real operator through a dev session; the local cookie is operator_session_local. With `rer dev --login`, follow the newest message and confirm it; no mail is sent. Preserve settings, owner and sessions on repeated setup. Use rer setup/dev/outbox as described in README.md. Outbox contents and token URLs are sensitive.

Settings invitations require the current native session, exact Origin and validated input. Invited operators have equal product authority; callers cannot choose a role. Base's last-owner protection also protects Vector's last operator. Operator removal atomically revokes mapped sessions, unused links and issued invitations, transfers product ownership, anonymizes retained history and preserves the last-operator/setup-owner guards. Failure rolls everything back.

Keep authentication mappings, cancellation ledgers and additive migrations on compatible-source rollback. Use isolated matching source and D1/R2 recovery before changing traffic. Archives exclude session tokens, sign-in links, development mail and secrets; restored installations require fresh native access and explicit review of other operators/effects. Local proof does not establish hosted email or provider acceptance.
