# Company agent access

Vector exposes one shared agent door at `/mcp`. It negotiates MCP 2026-07-28 and 2025-11-25. Discovery is at `/.well-known/oauth-protected-resource/mcp`. People use `/agents` to inspect policy, pause agents, review work and read the audit. Signed company policy arrives at `/api/rer/agent-policy`; signed Business settings bind the installation owner before Business access tokens can act.

The declared specialist is a software delivery coordinator. Its current jobs are workspace metadata, visible issue lists and activity, search, issue creation and version-checked edits, internal comments, and creating, accepting, deferring and declining intake. `agent-surface.json` lists the exact tools, scopes, clauses and verification journey. These tools call Vector's native services and role-matrix decisions. Imported descriptions, comments, titles and evidence remain untrusted data. Text in a record cannot grant authority or approve an action.

The declared capabilities are tools, policy, pause, audit, idempotency and resources. Issue and triage tools return named `vector://issue/{id}` resource links. Comment writes also return `vector://comment/{id}`, using the native discussion projection with its body, attribution and per-person action permissions. `resources/read` requires `evidence:read` and uses the same current native authority and issue/evidence projection as the app, including private-team visibility. An issue-read scope alone cannot read resource evidence. Events, prompts and subscriptions remain undeclared and return `capability_not_declared`. Project, cycle and document writes are not in the declared subset and have no resource templates yet.

The native people store is `operators`, joined to current Base authentication through `vector_auth_operators`. The signed Business `owner_id` binds only to `workspace_installation.setup_operator_id`. Token email never selects an account. Unknown subjects, removed or inactive people, changed token email, missing consent and revoked consent are refused. Native role and team visibility are checked for each call; queued approvals re-read the person. A local promotion grants no Business policy-editor role. Business teammate reconciliation, multiple sponsors and their independent proof are not offered yet.

Existing native API tokens can use only their original scopes. They name their issuing native person and their token client, and revocation or narrower scopes stop subsequent effects. They remain API credentials; they grant no browser session, installation, device or connector access. A recognizable failed Business token cannot fall through to this adapter.

Every write retains the native sponsor id and an activity label of `<agent> for <person>`, with its original operation id and named approver ids. Native activity produces an agent entry in the workspace audit in the same transaction. The agent remains the preparer. No native Undo is advertised by this subset. Native sessions, Origin checks, CSRF controls and all existing credential purposes remain in force.

No spending, paid dispatch, coding-agent delegation, customer messaging, merges, releases or deployments are offered. There is no provider cost registration. Imports, connectors and installation continue through their existing doors. The broader AGENT and AUTO clauses remain their existing targets; this door does not implement their missing workflows. Provider delivery, durable queued agent jobs, multi-sponsor lifecycle, change notifications and custody/erasure of retained door artifacts require their own proof before those families are claimed. Once an agent has been admitted, imported-person erasure is held with `agent_custody_unavailable`; the native erasure transaction also fences concurrent agent admission. This keeps the custody boundary closed until retained artifacts can be redacted without enabling pending execution or losing required evidence.

Contributors run normal `rer verify`. It builds a disposable production installation with the actual additive migrations, completes Vector's signed owner claim, binds Business ownership and exercises the declared native journey. No production credential or alternate application authentication adapter is used. Existing test suites remain unchanged.
