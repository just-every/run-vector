# Vector’s agent door

Vector serves one shared agent door at `/mcp`, with MCP 2026-07-28 and 2025-11-25, and native person controls at `/agents`. Signed company policy governs private reads and internal actions. Unset or expired policy, Pause, revoked consent and withdrawn native access refuse work.

The registry covers implemented issue creation and edits, intake decisions, discussions, checklists, reactions, links, relationships and bulk work; project, milestone, team workflow, label, cycle, initiative, release and document planning; streams, search, saved views, preferences, notifications, subscriptions, reporting, dashboards and workload. [The registry](AGENT-REGISTRY.md) lists every tool, class and current contract citation. `agent-surface.json` carries the matching resource catalogue and executable journey. It does not claim that Vector implements every proposed contract job.

Every mutation calls Vector’s native service as the current sponsor through its existing role decision and transaction fence. The door computes classes and exact summaries on the server. Internal work is `standard`; native grant changes are `access`, protective settings also carry `security`, and permanent erasure is `destructive`. Counts and widening decisions come from current native records. Stored native revisions protect edits. Provider costs are not registered, and spend is declared `none`. A record’s descriptions, imported evidence, comments and document text remain untrusted content.

Resources cover visible issues, discussion, retained history, links and relationships; projects, milestones, cycles, teams, labels and statuses; initiatives, releases, documents and templates; saved views, dashboards, notifications, reminders, subscriptions and personal preferences. Current native people and resource readers govern each read and retained event. Missing and inaccessible records have the same refusal. Bearer values and authentication secrets are never resources.

Business `owner_id` binds to the native installation owner. Signed team IDs bind to admitted native people. A Business team admin is a policy editor; a team member is not. A local promotion cannot grant a Business role. Email changes do not reassign bindings, held work or attribution. Company roster delivery does not create native accounts or widen their roles.

Agent activity retains the agent, sponsor, originating consent and named approvers inside the same native transaction. Native timelines and comments show “Agent for Person”; native person IDs continue to govern access. Ordinary person issue, project, document and audit activity is mirrored through `door.emit`; archive transport keeps its own custody lifecycle. Archives retain historical attribution, excluding active policy, bindings, pending approvals and transient transaction context. Restore requires fresh company settings and policy.

## Declared capabilities and current limits

This adoption declares core only: tools, policy, pause, audit and idempotency, with principal authorization and owner-bound tokens always required. Events/subscriptions, multi-sponsor, mail edges, resource refresh, timed lifecycle, dual host, queued lifecycle and owner-native administration are undeclared. The built-in event tool remains as Base emits it, and existing native person mirrors remain; neither claims complete event-family conformance. Released rer 0.2.86 has no subset declaration key. No unsupported manifest key is added.

Released Base supplies durable operation identity, the original idempotency key, effective scopes, consent, client identity and immutable approvers. Vector persists that context in the same native D1 transaction as issue, comment, project, document and audit attribution. Accepted replay uses Base's retained result after current admission checks; changed arguments conflict. The native public-door consent probe checks one-effect replay and the persisted original identity.

Queued lifecycle and mail edges remain undeclared. Vector refuses agent mutations with `native_queue_context_required` when an outbound destination, Slack installation or mail recipients beyond the sponsor are configured. This happens before outbox creation and is fenced again in the native transaction. Native person provider paths keep their credentials and delivery ledgers. No provider is reachable through the declared agent mutations. Spend is `{none:true}`; paid budgets are not enforced.

OAuth app grants and personal API tokens keep their existing purpose; neither authenticates at MCP. Failed recognizable Business credentials never fall through. Signed native owner claim and the native first-workspace flow initialize disposable verification installations. Client erasure cannot claim custody over retained door arguments, outcomes, summaries, audit and events: Base's generic client erasure fence remains absent.

Native membership, permission, privacy, role and removal tools retain native authorization. Their positive multi-person lifecycle, escalation and strict-subset proofs remain pending the undeclared multi-sponsor family. No extra accounts, substituted sessions or no-op widening proof is introduced. Membership revocation keeps both native identifiers (`id` for the team and `operatorId`); 0.2.86 refuses the checked two-key narrowing declaration at `conformance/narrowing.mjs` and `registry.ts`. The runtime keeps its real authority callback as an ordinary access tool; the surface retains the failing checked-contract assertion pending Base conformance-1 (base#661, 0.2.87). No surrogate single-key identifier is introduced. Binary upload, installation, imports and configured connectors retain explicit non-tool doors. Target-only jobs, provider/model dispatch, coding-agent delegation, merge and deployment are unavailable.

`rer door clauses --write` delivers BASE-AGENT-001 through 013 as missing; their judgment remains ct's. G7's missing BASE-AGENT-010 citation is repaired by that delivery. The installed npm CLI runs normal `pnpm exec rer verify` with its failure exit preserved. The independent production installation journey retains all declaration failures and runs the copied release's exported runtime assertions, including current replay admission and native audit target checks. A pending assertion is never reported as passed. In 0.2.86 the current-admission replay path resolves targets and reclassifies before returning cached outcomes; deleted native records therefore prevent an approved retry from returning its retained receipt. Current no-op authority direction also differs from the original widening expectation. Those assertions remain failing pending Base fixes. The target conformance reader misses rows beyond the first audit page; the focused native probe independently checks the persisted target.

Every shared transport route is mounted explicitly before application redirects and registered with its real `agent.owner-bound`, `business.signed-policy`, `person.session` or `public.metadata` identity and native authority. The existing ROLE-008 census checks these declarations against actual Hono routes as well as the ordinary role-matrix doors.
