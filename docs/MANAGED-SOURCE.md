# Managed source preparation

Vector vendors Base delivery-producer, owner-claim and editor source from the Base main revision recorded in [Base adoption](BASE-ADOPTION.md). `scripts/delivery/base/packaging.json` is the one packaging policy, selecting the same canonical `rer-setup.json` that local installation reads. The Base exporter adjusts only the producer setup-reader schema import locations; this exported adaptation is recorded in edition provenance, while exact runtime/schema copies are recorded by the existing source tool.

Run `pnpm run build`, then `pnpm run artifact:delivery` for a schema-2 Worker package. The thin caller performs no deployment. `rer-project.json` and `.github/workflows/rer-managed.yml` are generated by that same producer; the workflow pins the reviewed trusted-build source to a full commit and is dispatch-only. No workflow is dispatched by this change. Production builds must supply reviewed public configuration; development sample data is restricted to loopback.

The signed owner claim uses deployment-controlled RER issuer, installation ID, exact application origin, canonical FIRST_OWNER_EMAIL and a public EC/P-256 key ring. SESSION_SECRET and the generated hidden SETUP_TOKEN remain server-only. A bare confirmation popup accepts the signed claim from its exact opener/issuer, waits for native POST, and creates an ordinary Base operator-auth owner/session. The permanent claim/bootstrap ledgers refuse another claim. Signed configuration suppresses automatic first-owner creation until admission; ordinary local setup still uses the existing configured-owner path. Existing initialized and restored installations cannot be claimed again.

`/api/editor/config` requires the current native owner session, its admitted Vector identity and destination restore access. All Vector operators retain equal authority under OPS-001; this adds no product roles. Missing configuration returns 503, anonymous/revoked access 403, and non-GET requests 405. The response contains only enabled state, exact management origin, installation ID and a lease of at most 30 seconds. The owner shell renews through the server, revokes synchronously when sign-out starts or authorization is lost, and surfaces configuration/auth failures. Silent server revocation is observed by the short lease.

Compiled visual edits are installed before hydration from `src/editor/visual-edits.json`. Each rendered destination, including sign-in and NotFound, owns readiness; navigation pauses the same copied runtime. Owner teardown preserves published compiled edits. Application HTTP CSP retains unrelated script/nonces and limits frame-src and frame-ancestors to self and the configured exact management origin. The actual management service must independently authorize the installation and supply its registered application frame-ancestors.

Apply 0024 forward. Preserve existing owners, sessions, all prior SQL and permanent admission state. Keep additive ledgers on compatible-source rollback; validate matching-source backups in isolated D1/R2 resources before traffic changes. Restore excludes claim/session credentials and requires fresh configuration/access/effect review. Tests use ephemeral synthetic signing keys and a labeled local management peer; they cannot establish hosted editor/service acceptance.

After a successful claim, the owner reviews the workspace at `/setup` and completes setup through its public action before entering `/app`. Existing completed installations retain their completion stamp.

Stage installation, trusted hosted build/attestation, real service authorization/header behavior, live accounts, the public flip and homepage remain with the owner.

The editor configuration is admitted only for the recorded installation owner, with the current native Base session and destination restore grant rechecked before returning it. Invited operators retain equal product access and do not receive an editor mount or owner warning. The editor grant is non-secret and expires; this management admission does not introduce product roles.
